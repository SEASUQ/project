Разработка разделена на последовательные коммиты: сначала логика и физика,
затем окно и графика, после этого взаимодействие с объектами, тесты,
автоматическая проверка и описание проекта. Таблица описывает распределение
модулей в истории Git.

## `CMakeLists.txt` — правила сборки

Это файл для CMake, а не исходный код игры. Он объясняет системе сборки,
какие исходники компилировать и какие библиотеки подключать.

- `project` задаёт название проекта и язык C++.
- `CMAKE_CXX_STANDARD` выбирает стандарт C++11.
- `game_logic` собирает `src/game.cpp` в отдельную библиотеку с правилами игры.
- `target_include_directories` позволяет подключать заголовки из папки `src`.
- Параметры `/W4` или `-Wall -Wextra -Wpedantic` включают предупреждения для игровой логики.
- `BUILD_GAME` позволяет отключить графическую часть и проверить только логику.
- `find_package` ищет уже установленную SDL2.
- `platformer` собирает `main.cpp` и `drawing.cpp`, затем подключает SDL2 и `game_logic`.
- `SDL2main` подключается при наличии, перед основной SDL2; это нужно для некоторых сборок Windows.
- `CTest` добавляет настройку `BUILD_TESTING` и возможность запуска проверок.
- `game_tests` собирает файл с тестами; `add_test` регистрирует его для команды `ctest`.

Если добавляется ещё один исходный файл, его нужно добавить в соответствующую цель сборки.

## `src/game.h` — общие данные игры

Заголовочный файл содержит структуры, константы и объявления функций.
Он позволяет разным исходным файлам работать с одним устройством игрового состояния.
Защита `#ifndef GAME_H` предотвращает повторное объявление этих данных при подключении.

Константы задают размер клетки, ширину и высоту карты, количество уровней,
максимальное число врагов и шаг физики `STEP`, равный 1/120 секунды.

| Тип | Что хранит |
| --- | --- |
| `Body` | Координаты левого верхнего угла, ширину и высоту прямоугольника |
| `Player` | Прямоугольник игрока, вертикальную скорость и признак нахождения на земле |
| `Enemy` | Прямоугольник врага, границы маршрута, скорость и признак того, что враг жив |
| `Screen` | Текущий экран: меню, игра, пауза, проигрыш или победа |
| `Game` | Карту, игрока, массив врагов, номер уровня, жизни, монеты, камеру и текущий экран |

`levelStartCoins` хранит число монет перед началом текущего уровня.
После смерти оно используется для отката монет этого уровня.
`camera` хранит горизонтальное смещение видимой области мира.

В конце файла объявлены `overlaps`, `solidAt`, `loadLevel`, `startGame`
и `updateGame`. Их реализации находятся в `game.cpp`.

## `src/game.cpp` — правила и физика

Этот файл не создаёт окно и не рисует изображение. Он изменяет данные `Game`:
координаты, скорость, карту, счётчики и состояние прохождения.
Поэтому его можно проверять без SDL2.

| Функция | Что делает |
| --- | --- |
| `overlaps` | Проверяет, пересекаются ли два прямоугольника. Простое касание границ не считается пересечением |
| `solidAt` | Проверяет наличие твёрдой клетки `#`. Левая и правая границы мира считаются стенами, пространство сверху и снизу карты — пустым |
| `platform` | Заполняет выбранный участок строки карты платформой |
| `pit` | Убирает клетки пола в двух нижних строках и создаёт яму |
| `coinLine` | Ставит монеты через одну клетку на заданном участке строки |
| `addEnemy` | Добавляет врага в обычный массив и задаёт его маршрут. Не превышает максимальное число врагов |
| `loadLevel` | Создаёт пол и платформы, расставляет ямы, монеты, врагов и флаг. Сбрасывает игрока и камеру, сохраняет счёт монет на начало уровня |
| `startGame` | Возвращает первый уровень, три жизни и ноль монет; включает игру и загружает уровень |
| `loseLife` | Отнимает жизнь. При наличии жизней восстанавливает текущий уровень и его исходный счёт монет; иначе включает экран проигрыша |
| `moveHorizontal` | Сдвигает игрока влево или вправо, проверяет стены и боковые стороны платформ, не даёт выйти за границы мира |
| `moveVertical` | Сдвигает игрока по вертикали, останавливает падение на платформе и прыжок при ударе снизу. Обновляет признак нахождения на земле |
| `updateGame` | Выполняет один шаг игры: движение, прыжок, гравитацию, проверку падения, перемещение врагов, столкновения с ними, сбор монет, финиш и движение камеры |

Вспомогательные функции с `static` доступны только внутри этого файла.
Это не шаблоны: так внутренние детали реализации не попадают в другие исходники.

В `updateGame` направление ограничивается значениями от -1 до 1.
Прыжок разрешается только с земли. Затем выполняются перемещения по двум осям.
Падение ниже карты отнимает жизнь. Живые враги двигаются между своими границами
и разворачиваются на концах маршрута.

Если игрок падает на врага сверху, враг становится неактивным, а игрок отскакивает.
При другом столкновении теряется жизнь. Собранная монета удаляется из карты.
Касание флага загружает следующий уровень или включает победу после третьего.
Камера следует за игроком, оставаясь внутри границ мира.

Карта состоит из символов: `#` — платформа, `.` — пустота, `o` — монета,
`F` — финиш. Расположение объектов можно менять в `loadLevel`.

## `src/drawing.h` — связь между циклом и рисованием

Это заголовок графического модуля. Он подключает тип `SDL_Renderer` из SDL2
и структуру `Game` из `game.h`, а затем объявляет функцию `drawGame`.
Благодаря этому `main.cpp` может вызвать рисование, не зная его внутреннего устройства.
Защита `DRAWING_H` предотвращает повторное подключение содержимого.

## `src/drawing.cpp` — изображение игры

Файл читает состояние игры и рисует кадр. Параметр `const Game&` означает,
что функции рисования не должны менять карту, жизни или координаты объектов.

| Элемент | Что делает |
| --- | --- |
| `rectangle` | Задаёт цвет и рисует заполненный прямоугольник средствами SDL2 |
| `FONT` | Хранит пиксельные изображения 26 латинских букв и 10 цифр размером 5×7 |
| `text` | Читает строку, находит символ в `FONT` и рисует его отдельными квадратиками с указанным масштабом |
| `centeredText` | Считает длину надписи и размещает её по центру окна |
| `background` | Рисует небо, солнце и дальний план. Дальний план смещается медленнее камеры |
| `drawGame` | Рисует меню либо игровой мир, объекты, игрока, счётчики и нужный экран поверх игры; выводит готовый кадр |

Для каждой клетки карты вычисляется экранная координата: мировая координата
минус смещение камеры. Клетки за пределами окна пропускаются.
Платформы состоят из коричневых блоков и зелёной верхней полосы;
монеты, враги и игрок тоже собраны из прямоугольников.

Сверху выводятся номер уровня, жизни и монеты. При паузе, проигрыше или победе
рисуется полупрозрачная панель с соответствующей надписью.
`SDL_RenderPresent` показывает завершённый кадр.

Файлы изображений и шрифтов не загружаются. Надписи в окне используют латиницу,
поскольку встроенный шрифт содержит только латинские буквы и цифры.

## `src/main.cpp` — запуск и главный цикл

Единственная функция файла — `main`, точка входа программы.
Она связывает ввод, игровую логику и отрисовку.

1. Проверяет наличие параметра `--smoke-test` для короткой проверки отрисовки.
2. Инициализирует SDL2, создаёт окно 960×640 и средство рисования.
3. Если аппаратное рисование недоступно, пробует программное.
4. При ошибке выводит причину, освобождает уже созданные ресурсы и завершает программу.
5. Создаёт начальное состояние с главным меню.
6. В цикле читает события: закрытие окна, клавиши и потерю фокуса.
7. Обрабатывает начало игры, паузу, перезапуск, прыжок и выход.
8. Определяет направление движения по состоянию клавиш.
9. Накапливает прошедшее время и вызывает `updateGame` с постоянным шагом физики.
10. Вызывает `drawGame`, затем при завершении освобождает средство рисования, окно и SDL2.

`jumpRequested` сохраняет одиночное нажатие до ближайшего шага физики.
Повторы клавиши от операционной системы игнорируются, поэтому удержание
пробела не вызывает цепочку прыжков.

`accumulator` хранит время, ещё не обработанное физикой. Если кадр занял дольше
одного шага, выполняется несколько шагов. Большая задержка ограничивается
0,1 секунды, чтобы игра не пыталась мгновенно догнать длительную остановку окна.

При потере фокуса включается пауза. Возврат фокуса сам по себе не снимает её:
для продолжения нужно нажать P. В режиме `--smoke-test` программа рисует
пять экранов — меню, игру, паузу, проигрыш и победу — и закрывается.

## `tests/game_tests.cpp` — автоматические проверки

Это отдельная программа с собственным `main`. Она работает с `Game` напрямую,
не создаёт окно и возвращает ненулевой код завершения, если найдена ошибка.
Этот код позволяет CTest и GitHub определить, прошла ли проверка.

| Элемент | Что делает |
| --- | --- |
| `failures` | Хранит число неудачных проверок |
| `check` | Проверяет условие, печатает описание ошибки и увеличивает счётчик ошибок |
| `tick` | Выполняет заданное число шагов физики с выбранным направлением движения |
| `disableEnemies` | Отключает врагов, чтобы отдельно проверить проходимость ям |
| `main` | Создаёт ситуации для проверки механик и сообщает общий результат |

Проверяются начало игры, устойчивость на полу, прыжок и запрет второго прыжка
в воздухе, пауза, левая граница, столкновения с платформой сбоку и снизу,
приземление сверху, однократный сбор монет, откат уровня после смерти,
потеря последней жизни, столкновения с врагом, победа над ним прыжком,
переходы между уровнями и окончательная победа.

Последняя проверка проходит все уровни обычными шагами физики и прыгает
при приближении к яме. Враги в ней отключены; их столкновения проверяются отдельно.
Это проверка проходимости ям, а не автоматическое прохождение всех врагов.

## `.github/workflows/build.yml` — проверка на GitHub

Этот файл задаёт GitHub Actions: при отправке коммитов или создании pull request
на сервере запускается задача `linux`.

Она получает исходники, устанавливает SDL2, настраивает CMake, собирает игру,
запускает тесты и проверяет отрисовку через `--smoke-test`.
Переменная `SDL_VIDEODRIVER=dummy` позволяет проверить создание окна и кадры
на сервере без обычного рабочего стола.

Файл не нужен для локального запуска игры. Он нужен для обнаружения ошибок
сборки и механик после изменений в репозитории.

## `.gitignore` — что не сохраняется в Git

- `/build*/` исключает папки сборки в корне, например `build` и `build-logic`.
- `/.idea/` и `/.vscode/` исключают локальные настройки редакторов в корне проекта.
- `*.exe`, `*.obj` и `*.o` исключают исполняемые файлы Windows и промежуточные объектные файлы.
- `.DS_Store` исключает служебный файл macOS.

Этот файл ничего не удаляет с компьютера. Он помогает не добавлять в коммиты
создаваемые при сборке файлы и настройки конкретного компьютера.

## Как файлы работают вместе

При сборке CMake объединяет исходники и подключает SDL2. При запуске
`main.cpp` создаёт окно и читает клавиатуру. Он вызывает `updateGame`
из `game.cpp`, чтобы изменить состояние `Game`, объявленное в `game.h`.
Затем вызывает `drawGame`, объявленную в `drawing.h` и реализованную
в `drawing.cpp`, чтобы показать новое состояние.

Тесты используют ту же игровую логику. GitHub Actions автоматически собирает
оба исполняемых файла и запускает проверки. README объясняет запуск,
а этот документ — устройство программы.

Каталоги сборки и `.git` не являются исходными файлами проекта:
первые создаются CMake, второй хранит служебные данные истории Git.
